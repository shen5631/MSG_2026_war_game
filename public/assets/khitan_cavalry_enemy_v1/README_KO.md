# 거란군 적 기병 — 이미지·코드 패키지

**일반 적 `cavalry`입니다. 보스, 아군 지원 스킬, 말 없는 창병이 아닙니다.** 기존 기획에서는 3라운드에 배치됩니다. 이번 자료 때문에 웨이브의 적 종류/수를 변경하지 않습니다.

## 먼저 열기

`START_PREVIEW.html`은 이미지와 동일한 빌드 제어 코드가 내장된 독립 Canvas 검사 화면입니다. 프레임 선택, 한 장 넘기기, 좌우 반전, 여백 표시, 돌진/피격/패링/사망/초기화를 확인할 수 있습니다. 화면의 패링 시험 버튼은 성공 결과를 강제로 준비하는 진단 기능이며 완성된 플레이어 패링 입력 시스템이 아닙니다.

브라우저의 로컬 파일 정책이 막으면 Node.js 설치 환경에서 `npm run demo`를 실행한 뒤 표시된 주소로 접속합니다. 이 명령은 npm 패키지 설치 없이 실행됩니다.

## 실제 이미지 파일

| 폴더 | PNG | 사용 |
|---|---:|---|
| idle | 4 | 대기 |
| walk | 6 | 일반 이동 |
| run | 6 | 질주 자세 |
| attack | 6 | 돌진 전 준비 3장 + 공격 후 복귀 3장 |
| charge | 2 | 창을 내민 실제 돌진, 2개의 서로 다른 포즈 반복 |
| hurt | 4 | 피격/패링 경직 |
| death | 6 | 기수·말이 무너짐, 최종 자세 |

**개별 PNG 34장, 서로 다른 최종 픽셀 데이터 34개입니다.** 2장짜리 charge를 6장이나 새로운 풀 애니메이션이라고 세지 않았습니다. run과 charge는 서로 다른 그림입니다. 모션 보간이나 신규 디테일을 만들어낸 업스케일이 아닙니다.

본체는 말과 기수를 하나의 스프라이트로 취급합니다. 그림 안에 글자, 설명판, 파일 트리, UI, 체크무늬가 들어 있지 않습니다. 원본의 배경과 구분선은 분리했고, 동작마다 다른 크기로 늘이지 않도록 공통 배율과 기준점을 적용했습니다.

- 프레임: **320×224 RGBA**. 실제 캐릭터는 여백보다 작습니다.
- 기준점: **(160,192)**. origin = **(0.5, 6/7)**.
- 기본 scale = 1, 오른쪽 기본, 왼쪽은 flipX.
- 실제 대기 본체 높이는 약 120px이며, 캔버스 높이 224px가 캐릭터 높이가 아닙니다.
- 모든 PNG의 캔버스 가장자리 여백 최소 26px 확인.
- 아틀라스 1600×1568, 프레임 회전/자동 trim 없음.
- source/masters는 분리 원본이며 새로운 초고해상도 그림이 아닙니다. 런타임에 로딩하지 않습니다.

## 폴더

public/assets/khitan_cavalry_enemy_v1에는 개별 PNG, 동작별 strip PNG/JSON, 통합 atlas PNG/JSON과 manifest가 있습니다. src/enemy에는 표시부와 선택적 제어기, lib에는 빌드된 JavaScript와 타입 선언, examples에는 연결 예제, tests와 validation에는 실제 실행한 검사 자료가 있습니다.

## 기존 프로젝트 적용

먼저 `CLAUDE_IMPORT.md`와 `docs/INTEGRATION_KO.md`를 읽습니다. **기존 AI가 있으면 `PhaserCavalryView`만 연결합니다.** 제어기와 기존 AI/물리 이동을 동시에 실행하지 않습니다. 기존 package.json을 이 패키지의 파일로 덮어쓰지 않습니다.

`preloadCavalry(scene)`를 Scene.preload에서 호출하고, 로딩 후 create에서 `new PhaserCavalryView(scene)`를 생성합니다. 기존 적의 위치, 바라보는 방향, 상태, 상태 경과시간을 sync에 전달합니다. 표시부는 피해·쿨타임·드롭·웨이브 처리를 하지 않습니다.

## 유지한 규칙

출처: 사용자가 제공한 강감찬 상세 개발 기획서 §10.1~10.3, §11.1.

HP70은 기존 확정값입니다. 피해18, 돌진속도260px/s, 시작거리160~320px, 예고850ms, 돌진최대600ms, 회복1000ms는 기존 문서의 구현 기본값입니다. 공격 방향은 예고 시작 때 고정하는 구현 기본값을 사용합니다. 돌진 중 플레이어를 따라 순간적으로 좌우 방향을 바꾸지 않습니다.

말 몸통 전체의 상시 접촉 피해는 없습니다. 돌진 중 창의 판정만 피해를 주며 패링 가능합니다. 한 공격 ID/대상 ID에는 접촉 처리를 1번만 합니다. 패링/무적/보호막/HP 처리는 프로젝트의 기존 순서를 유지합니다. 벽에 막히면 돌진이 끝나고 방향을 바꿉니다. 사망 집계는 killed 이벤트에서 1회 처리하고, 시체 프레임 수로 여러 번 세지 않습니다.

선택적 제어기의 평시 보행60px/s, 별도 질주120px/s, 피격220ms, 패링 경직650ms, 사망 표현900ms, hurtbox/weaponbox는 **새 구현 기본값**입니다. 기존 게임에 대응 값이 있으면 기존 값을 우선합니다. 이 제어기는 완성된 지형/낭떠러지 AI가 아닙니다. 이동 충돌은 resolveMove 또는 기존 물리 엔진에 연결해야 합니다.

## 검사와 제한

`npm test`는 설치 없이 Node.js에서 빌드된 lib를 검사합니다. TypeScript 개발 의존성이 있는 환경에서는 `npm run typecheck`, `npm run build`를 실행합니다. 이미지 검사는 Python의 Pillow/numpy가 필요합니다.

검사 결과는 validation/VALIDATION_KO.md에 있습니다. **실제 Phaser 엔진과 사용자의 기존 게임 전체를 실행한 검사는 아닙니다.** Canvas 테스트, 파일 검사, 구조형 표시 어댑터의 테스트와 엔진 통합은 별개입니다. 무오류를 보장하는 표현 대신 수행한 검사 범위를 기록합니다.
