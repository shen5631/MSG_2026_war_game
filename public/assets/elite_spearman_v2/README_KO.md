# 정예 창병장 — 수정 패키지 V2

이전 `elite_spearman_commander_round2_boss_v1`을 대체하는 **2라운드 보스** 이미지·코드 묶음입니다.
일반 적 창병 / 아군 창병 스킬 / 1라운드 선봉대장 / 기마 보스가 아닙니다.

## 1. 바로 확인

`START_PREVIEW.html`을 열면 외부 이미지·라이브러리 다운로드 없이 동일한 보스 제어 코드의 Canvas 검사 화면이 표시됩니다.
브라우저 보안 설정으로 로컬 파일이 차단되면 Node.js로 다음 명령을 실행하세요.

```bash
npm run demo
```

출력되는 로컬 주소로 접속합니다. 이 명령에는 npm install이 필요 없습니다.
검사 조작: A/D 이동, Space 점프, J 검사 공격, L 패링, Esc 일시정지.
오른쪽에서 각 동작과 개별 프레임, 밝은/어두운 배경, 좌우 반전을 확인할 수 있습니다.
이 화면은 개발용 검사 장면이지 기존 3라운드 게임 전체가 아닙니다.

## 2. 그림 수정

이전 파일은 가로 시트를 일정 폭으로 잘라 창이 다른 칸으로 넘어갔고, 낮은 알파값의 잡음 때문에 잘못된 크기로 정렬됐습니다.
V2는 원본에서 몸체와 무기를 연결 윤곽으로 추출하고, 동작별 제작 배율을 보정했습니다.

- 인물과 창을 함께 보존하고 이웃 인물/창 조각을 제거했습니다.
- source alpha 128 미만의 반투명 배경 잡음을 제거하고 몸체는 0/255 알파로 정리했습니다.
- 원본 끝에서 잘린 대기 4번·이동 6번의 창날을 같은 동작의 온전한 창날로 교체했습니다.
- 원본 색상과 하이라이트를 유지했습니다. 반복 JPEG 저장이나 전체 그림 흐림 처리를 하지 않았습니다.
- 공통 프레임: **320×192 RGBA PNG**.
- 기준점: **(160,176)**. 게임의 x/y는 발 중앙입니다.
- 640×360 내부 화면에서 **scale=1**을 기본으로 합니다. 몸체 높이는 대기/걷기 기준 약 105px입니다.
- 프레임 폭 320은 긴 창을 포함하는 투명 여백입니다. 캐릭터 몸통이 320px라는 뜻이 아닙니다.
- 아틀라스는 1620×1960, 각 프레임 사이 4px 투명 간격입니다.

**setDisplaySize(128,128), alpha bbox 자동 크롭, 비율이 다른 폭/높이 맞춤을 적용하지 마세요.**
캐릭터가 작아지거나 창이 잘리는 문제가 다시 생길 수 있습니다.

## 3. 포함 동작: 50 PNG / 9종

| 폴더 | 장수 | 연결 |
|---|---:|---|
| idle | 4 | 대기 |
| walk | 6 | 이동 |
| long_thrust | 6 | 긴 창 찌르기 |
| sweep | 6 | 근접 휘두르기 |
| double_thrust | 8 | 2페이즈 연속 찌르기 — 실제 타격 2회 |
| jump_slam | 6 | 2페이즈 점프 내려찍기 |
| phase2 | 4 | 2페이즈 전환 |
| parry_stagger | 4 | 패링당한 뒤 경직 |
| death | 6 | 패배 |

장수는 애니메이션 단계 파일 수입니다. **50개의 서로 다른 신규 그림을 새로 그렸다는 의미가 아닙니다.**
`double_thrust`는 보정된 찌르기 포즈를 반복 조합합니다. `sweep`는 기존 창 휘두르기 포즈를 재배열했습니다.
`jump_slam`은 온전한 웅크림·창 들기·무릎 착지 포즈를 재사용하고, 실제 공중 이동은 코드로 처리합니다.
완전히 새로운 공중 포즈 시트를 생성한 것으로 표시하지 않았습니다. 재사용 내역은 manifest와 validation/source_processing.json에 있습니다.

## 4. 코드 포함 내용

- `src/boss/config.ts`: 원래 기획의 HP·패턴·시간 기준.
- `EliteSpearmanController.ts`: 프레임 레이트에 의존하지 않는 제어, 2페이즈, 공격창, 중복 적중 방지, 패링, 점프 목표 고정, 일시정지, 리셋.
- `presentation.ts`: 상태/경과 시간에 따른 정확한 PNG 선택.
- `PhaserEliteSpearmanView.ts`: 렌더링 전용 연결부. HP·피해·AI를 중복 생성하지 않음.
- `lib/boss/`: 위 코드의 빌드된 JavaScript와 타입 선언.
- `examples/`: 기존 게임 연결 예제와 Phaser 3.90 실행 예제.

기존 보스 로직이 이미 있으면 **View만 교체**하세요. 새 컨트롤러와 기존 보스 AI를 동시에 실행하지 마세요.

## 5. 원래 기획 유지

최대 HP 500, HP가 250 이하이고 살아 있으면 2페이즈. HP0이면 전환보다 처치 우선.
페이즈 전환 900ms, 전환 중 무적. 일반 피격마다 경직하지 않고 패링에 650ms 경직.
긴 찌르기·가까운 휘두르기·연속 찌르기·붉은 점프 내려찍기만 기본 AI에 연결합니다.
이전 v1의 `charge`를 새로운 돌진 패턴으로 추가하지 않습니다. 창 투척이나 투사체도 추가하지 않습니다.
정확한 시간은 `docs/RULES_KO.md`를 읽으세요.

## 6. 실행/검증

```bash
npm test               # 빌드된 lib 기준 Node 테스트: 의존성 설치 불필요
npm run demo           # 독립 Canvas 검사 화면
npm install            # TS 재빌드 또는 Phaser 예제를 실행할 때만
npm run typecheck
npm run build
```

`PHASER_DEMO.html`은 npm install 후 로컬 서버에서 엽니다. Phaser 3.90.0을 사용하는 별도 연결 예제입니다.
이 패키지의 package.json을 기존 게임에 덮어쓰지 마세요.
이미지 검사 재실행에는 Python + Pillow가 필요합니다: `python tools/verify_images.py`.

## 7. 실제 검증 범위

이미지 규격/알파/여백/아틀라스/스트립 검사 **362/362**, Node 코드 테스트 **37/37**, TypeScript 5.8.3 정적 검사 통과.
Chromium의 Canvas 검사 화면에서 **70/70** 검사, JavaScript 예외 없음.
현재 환경의 브라우저 로컬 URL 접근 제한 때문에 HTML 본문을 `page.set_content`로 로딩하여 검사했습니다.
HTTP/file:// 탐색 자체와 **실제 Phaser 엔진 실행, 사용자의 기존 게임 통합, 실물 게임패드**는 이번에 검증하지 못했습니다.
Phaser 연결부는 정적 타입 검사 및 구조를 모사한 어댑터 테스트를 수행했습니다. 이것을 실제 엔진 테스트로 부르지 않습니다.
검증 결과 전체는 `validation/`에 있습니다.
