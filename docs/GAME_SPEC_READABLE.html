강감찬: 고려의 수호자

Claude Code 개발 착수용 상세 기획서 · v1.0

작성 기준: 2026-10-22 / 대상: React + Phaser + TypeScript + Vite / 우선 실행 환경: PC Chrome

이 문서는 지금까지 사용자가 결정한 게임을 실제로 구현하기 위한 명세다. 문서 요약이나 재기획만 하지 말고, CLAUDE.md와 IMPLEMENTATION_PLAN_KO.md의 순서에 따라 실행 가능한 코드를 작성한다. 3라운드·모든 전투 기능·엔딩·결과 화면이 구현 범위다. 제공된 그림이 완성 게임 전체의 리소스라고 가정하지 않는다.

0. 읽는 순서와 결정의 우선순위

0.1 문서 표기

  • [확정]: 대화에서 사용자가 선택한 규칙. 편의·시간 부족·엔진 제약을 이유로 조용히 바꾸지 않는다.
  • [구현 기본값]: 기존 대화에 정확한 수치/처리가 없어 이 문서에서 최초 구현용으로 정한 값. 별도 질문을 반복하지 않고 구현하되, 설정 파일에 분리하고 테스트 결과에 따라 조정한다. 기존 승인 사항인 것처럼 보고하지 않는다.
  • [리소스 사실]: 이번 패키지 안의 파일을 검사하여 확인한 내용.
  • [출시 검증 필요]: 코드 구현·실기 테스트·최종 그림/음원 교체가 필요한 사항. 기획 문서 작성만으로 완료 처리하지 않는다.

의도적으로 변경하지 않은 중요한 수치: 1단계 차징 피해 20은 일반 강공격 25보다 작다. 이는 확정값이므로 임의 상향하지 않는다. 총 플레이 시간 10~15분은 목표이지 아직 실측한 결과가 아니다.

1.2 반드시 구현할 범위

주인공의 모든 확정 행동, 일반 적 5종, 보스 3종과 각 2페이즈, 지원병 스킬 3종, 회복 아이템 2종, 강화 보상 3종, 전체 UI 흐름, 재도전·일시정지·입력 예외, 스토리 엔딩과 기록 화면을 구현한다.

게임 규칙은 완성하고, 미완성 리소스는 상태를 명시한다. 개발용 포즈 재활용으로 기능을 연결할 수는 있지만, 이를 모든 전용 애니메이션의 최종 완성이라고 보고하지 않는다.

이번 범위 밖: 멀티플레이, 로그인, 서버, 클라우드 저장, 상점, 장비/인벤토리, 경험치 레벨업, 절차적 맵, 랭킹 서버, 모바일 터치 조작, 모든 게임패드의 호환 보장, 유료 서비스 자동 가입.

1.3 역사와 창작의 구분

젊은 강감찬의 검술 결투·지휘 스킬·1~2라운드 보스는 게임적 각색이다. 엔딩에서는 “1019년 고려군이 귀주에서 거란군을 크게 물리쳤다”는 역사적 사실과 창작 장면을 분리한다. 게임에서 보스 HP를 0으로 만드는 것은 승리 조건이지, 실제 소배압을 강감찬이 직접 죽였다는 역사 설명이 아니다. [H01]

엔딩에 사용할 문안은 §18에 제공한다. 왕의 이름·병력 수·현대 지명을 추가로 창작하지 않는다.

2. 기술 기준과 프로젝트 구조

2.1 확정 기술

Claude Code로 코드 작성, React로 메뉴/오버레이, Phaser로 게임 렌더링·캐릭터·충돌·맵, TypeScript로 구현, Vite로 개발 서버/빌드. Chrome 우선, Xbox형 standard 게임패드 우선, 키보드도 지원한다. 전체 화면을 제공한다.

2.2 버전 선택 [구현 기본값]

이번 단기 구현은 Phaser 3.90.0을 정확히 고정한다. 최신 버전이라는 의미가 아니다. 확인 시점의 공식 기본 문서는 Phaser 4.1.0이며, 3.90 문서는 별도로 보존되어 있다. API/예제 혼용을 막기 위한 호환성 기준이다. phaser@latest로 설치하거나 작업 중 4.x로 자동 변경하지 않는다. 3.90 유지보수 종료 표시는 출시 전 기술부채로 기록한다. [T02][T03]

Node는 22.12 이상인 22.x를 기본 환경으로 한다. Vite 공식 문서의 Node 요구 사항과 선택한 패키지의 engines를 실제 설치 시 확인한다. React/TypeScript/Vite/Vitest/Playwright는 서로 호환되는 안정판을 한 번 선택해 정확한 버전과 package-lock.json을 고정한다. --force 또는 --legacy-peer-deps로 충돌을 숨기지 않는다. [T04]

게임은 HTTP 개발 서버 또는 HTTPS 정적 배포에서 실행한다. index.html을 file://로 직접 여는 방식을 실행 방법으로 안내하지 않는다.

3. 전체 상태 흐름

BOOT → PRELOAD → TITLE → ROUND_1
                        ├─ 사망 → GAME_OVER → 현재 라운드 재시작
                        ├─ 일시정지 → PAUSE → 동일 상태 재개
                        └─ 1보스 승리 → REWARD_1 → ROUND_2
                                                └─ 2보스 승리 → REWARD_2 → ROUND_3
                                                                        └─ 최종 승리 → ENDING → RESULTS → TITLE

LOAD_ERROR는 PRELOAD에서 진입하여 오류 안내와 다시 시도 버튼을 표시한다. 재시도 성공 전에는 실제 게임을 시작하지 않는다.

라운드 내부는 TRAVERSAL → ARENA_SPAWN → WAVE_ACTIVE → WAVE_GAP → … → ARENA_CLEAR → TRAVERSAL → BOSS_INTRO → BOSS_PHASE1 → PHASE_TRANSITION → BOSS_PHASE2 → ROUND_CLEAR다.

게임 오버/보상/엔딩은 전투 장면 위의 단순 UI가 아니라 전투 입력·판정이 멈춘 명확한 상태다. 전투 상태와 UI 상태를 독립적인 불리언 수십 개로 조합하지 않는다.

4.2 장치 우선순위

지원 가능한 활성 게임패드가 연결된 동안에는 패드가 전투 입력을 우선 소유한다. 키보드 이동/공격을 섞지 않는다. 처음부터 지원 패드가 없으면 키보드로 시작할 수 있다.

패드가 여러 개면 최초 활성 표준 패드 한 개를 선택한다. 다른 패드의 이벤트로 현재 플레이어가 갑자기 이동하지 않는다. 지원하지 않는 패드는 안내하고 키보드 시작을 허용한다. 장치 이름만 보고 비표준 매핑을 추측하지 않는다.

[구현 기본값] 스틱 데드존 0.20. 트리거 눌림 0.55 이상, 놓임 0.35 이하의 히스테리시스. 데드존 밖은 아날로그 이동 세기를 반영한다. 좌우 키를 동시에 누르면 이동 0, 바라보던 방향은 유지한다.

게임패드 폴링은 렌더 프레임마다 한 번 수행하고 이전 버튼 상태와 비교해 pressed/held/released를 구분한다. 30FPS에서 한 프레임 사이의 매우 짧은 물리 버튼 입력을 완벽히 복원할 수 있다고 가정하지 않는다.

4.3 B+Y / J+K 동시 입력

[확정] 두 버튼의 누름 시작 간격 100ms 이하면 동시 입력 후보다.

[구현 기본값] 두 버튼이 실제로 겹쳐 눌려 있어야 한다. 순서는 B→Y, Y→B 모두 허용한다. 이미 완료된 약공격을 소급 취소하여 차징으로 바꾸지 않는다.

첫 버튼을 받으면 최대 100ms의 미확정 공격 의도를 만든다. 시각 준비 동작은 시작할 수 있지만 피해는 확정 전 발생시키지 않는다. 두 번째 버튼이 허용 구간에 들어오면 일반 공격 의도를 취소하고 차징으로 전환한다. 차징 시간은 두 버튼이 동시에 유지되기 시작한 시점부터 센다.

동시 입력이 아니면 최초 버튼의 일반 공격을 확정한다. 미확정 대기시간은 해당 공격의 준비시간에 포함하며 추가 100ms를 다시 붙이지 않는다. 약공격 1타의 준비시간이 100ms인 이유다.

이미 실행 중인 공격의 이후 입력은 버퍼에 저장한다. 현재 타격이 끝나 다음 행동을 시작할 때 해석한다. 3타가 확정된 이후 새 Y 입력은 마무리 후보이며, 이미 소비한 B 입력과 다시 차징 조합을 만들지 않는다.

단일 버튼·차징·마무리 3종의 경계(99/100/101ms), 두 버튼 중 한쪽을 먼저 놓은 경우를 반드시 테스트한다. 키 반복 event.repeat로 새 공격을 만들지 않는다.

4.4 화면별 입력 소비

메뉴 확인은 패드 A, 키보드 Enter/Space. 취소는 패드 B, 키보드 Esc. 메뉴 이동은 스틱/D-pad 또는 방향키/WASD. 방향 반복은 최초 300ms 후 150ms 간격 [구현 기본값].

화면을 바꾼 버튼은 그 화면에서만 소비한다. 새 화면에서는 해당 버튼이 놓인 뒤 새로 눌려야 동작한다. 게임 시작 A가 점프를 만들거나 보상 확정 A가 엔딩을 건너뛰게 하지 않는다.

일시정지·사망·장치 변경·화면 전환 시 전투 예약 입력을 비운다. 단, 현재 진행 중인 차징/공격의 게임 상태는 일시정지로 초기화하지 않는다. 재개 직후 입력 기준 상태를 다시 잡고, 눌려 있던 키를 새 입력으로 취급하지 않는다.

4.5 브라우저 단축키 충돌

Ctrl 달리기와 D/E/J/K/L 조합은 Chrome 기능과 충돌할 수 있다. 확정한 키를 임의 변경하지 않고, 게임 영역에 포커스가 있고 해당 액션을 소유할 때만 취소 가능한 이벤트에 preventDefault를 적용한다. 운영체제/브라우저가 예약한 모든 단축키를 막을 수 있다고 보장하지 않는다. 포커스가 빠지면 입력을 해제하고 안전 일시정지한다 [구현 기본값]. 실제 Ctrl+D, Ctrl+E, Ctrl+L, Ctrl+Shift+J 조합을 수동 검수하고 실패를 보고한다.

5. 주인공 이동과 물리

5.1 이동 규칙

좌우 이동, 1단 점프, LT/Ctrl을 누르는 동안 달리기, RT/Shift 공격형 대쉬를 구현한다. 공격 중 이동은 평소보다 느리고, 개별 검격이 진행되는 동안 공격 방향은 고정된다. 다음 콤보 타격 시작 시 현재 좌우 입력을 반영한다. 중립이면 기존 방향을 유지한다.

[구현 기본값] 걷기 110px/s, 달리기 180px/s, 검술 중 걷기 속도의 50%, 차징 중 30px/s. 공격 중 달리기 키가 눌려도 빠른 달리기로 덮어쓰지 않는다. 점프 초기 속도 -430px/s, 중력 1200px/s². 단순 장애물은 32~48px 높이 중심. 공중 이동 계수 0.8. 코요테 타임 80ms, 점프 입력 버퍼 100ms. 이중 점프/벽점프는 추가하지 않는다.

5.2 바디와 그림

플레이어 물리 좌표는 발 중앙을 기준으로 한다. 기본 몸통 AABB는 32×72px [구현 기본값]. 그림은 128×128, origin=(0.5, 114/128). 그림의 검/망토/투명 여백을 피격 바디로 사용하지 않는다.

그림 프레임 변경이나 좌우 반전으로 발바닥 충돌 위치가 움직이지 않아야 한다. 점프 그림 자체의 상승 오프셋과 물리 점프를 중복 적용하지 않는다. 검격 히트박스는 몸통 바디와 별도로 생성한다.

5.3 대쉬

[확정] 공격형이며 무적이 없다. 공격 중 대쉬로 현재 공격을 취소할 수 있다. 차징 중 대쉬는 충전을 취소한다. LT 달리기 중 RT가 들어오면 대쉬가 우선이다.

[구현 기본값] 시작 시 바라보는 방향으로 480px/s, 공격 이동 180ms, 후딜레이 120ms, 시작 기준 재사용 600ms. 대쉬 중 동일 적에게 1회만 기본 피해 15. 벽을 통과하지 않는다. 이동 경로에 적이 있어도 물리적으로 막히지 않도록 적-플레이어 몸체 충돌은 분리하고 공격 판정만 계산한다. 패링 불가 공격을 대쉬로 정면 통과해 무효화할 수는 없다.

공중 대쉬는 첫 구현에 넣지 않는다 [구현 기본값]. 공중에서 RT를 눌러도 착지 후 자동 실행을 예약하지 않는다.

7. 패링, 피격, 보호막

7.1 패링 [확정]

X/L 실행 후 기본 200ms 성공 판정. 패링 강화 1회당 +50ms, 최대 300ms. 성공하면 적을 경직시키고 플레이어가 직접 B/Y 등으로 반격한다. 자동 반격 피해는 없다. 실패하면 짧은 후딜레이. 성공 순간 화면 정지 효과를 적용한다.

[구현 기본값] 앞쪽 공격만 패링 가능, 공중 패링 없음. 성공 즉시 패링 상태를 끝내고 직접 공격 가능. 일반 적 경직 1000ms, 보스 경직 650ms. 실패 후딜레이 180ms. 성공 히트스톱 60ms. 길게 누르기/키 반복으로 패링 판정을 무한 연장하지 않는다.

반짝이는 별도 타이밍 아이콘을 보스 일반 공격에 추가하지 않는다. 일반 공격 예고는 준비 동작만. 강력한 패링 불가 공격은 보스 붉은빛으로 구분한다.

화살 패링은 투사체를 제거하고 성공 횟수에 포함한다. 화면 밖 궁병을 원격 경직시키거나 화살을 반사하는 효과는 기본값에 포함하지 않는다.

7.2 HP 피격 [확정]

보호막을 넘는 HP 피해가 발생하면 짧은 경직, 현재 공격/차징 취소, 콤보 초기화, 500ms 추가 HP 피해 무적. HP가 0이면 사망이다. 무적 중 동일/다른 공격 모두 피해를 주지 않는다.

[구현 기본값] 경직 180ms. 짧은 넉백과 깜빡임으로 표시. 무적 시작은 피해가 실제 적용된 시각이다. 접촉만으로 피해를 주지 않고 각 적 공격의 활성 히트박스/투사체로 판정한다.

7.3 보호막 [확정]

초기 40, 최대 5초, 초당 자연 감소 8. 적 공격은 HP보다 보호막에 먼저 적용한다. 전부 흡수하면 경직/피격 무적이 생기지 않는다. 초과분만 HP에 적용되고 그때 경직·500ms 무적이 발생한다.

shieldAfterDecay = max(0, shieldBefore - 8 × dtSeconds)
absorbed = min(shieldAfterDecay, incomingDamage)
hpDamage = incomingDamage - absorbed
shieldAfterHit = shieldAfterDecay - absorbed

보호막이 정확히 15 남았을 때 피해 15를 받으면 보호막은 0이 되지만 HP 피해 0이므로 경직 없음이다. 10 남았을 때 15를 받으면 HP 피해 5와 경직이다.

보호막 자연 감소는 실수값으로 누적한다. 매 프레임 반올림하지 않는다. 공격 최종 피해의 반올림과 보호막 시간 감소 계산은 다른 처리다. 보호막 초과 피해로 HP 내부값이 소수가 될 수 있으므로 내부 HP도 실수로 보관하고, HUD에는 양수 HP를 올림해 보여준다 [구현 기본값]. HP 0 판정은 실제 내부값으로 한다.

파괴되거나 최대 5초가 되면 방패병 시각 효과를 제거한다. 공격을 받지 않으면 5초에 0이 된다. HP 무적 중 공격은 보호막도 깎지 않는다 [구현 기본값].

7.4 피해 판정 순서

  1. 공격 인스턴스와 대상의 유효/생존 상태, 같은 공격 중복 적중 여부 확인.
  2. 전투 종료/일시정지/페이즈 무적 등 면역 조건 확인.
  3. 패링 가능한 공격이고 전방·시간 조건을 만족하면 패링, 피해 0.
  4. HP 피격 무적이면 피해 0.
  5. 최종 공격 피해 계산 → 보호막 흡수 → HP 초과 피해.
  6. 피해가 실제 적용된 결과에 따라 경직/콤보 취소 처리.
  7. 같은 시뮬레이션 틱의 모든 사망 후보를 모은 뒤 승패 확정.

attackInstanceId + targetEntityId 적중 기록으로 프레임마다 반복 피해를 방지한다. 보스 3연타는 타격별 별도 attackInstanceId다. 이미 죽은 적에게 추가 접촉해 처치·드롭을 재발생시키지 않는다.

8. 지휘 스킬

8.1 공통 [확정]

LB/Q를 누를 때 지휘 강화 → 창병 공격 → 방패병 막기 → 지휘 강화 순환. RB/E로 현재 선택 스킬 발동. 기본 20초 공유 쿨타임. 하나를 쓰면 모두 잠긴다. 쿨타임 중에도 선택 변경은 가능하다.

검술 도중 지휘 강화/방패병은 즉시 발동해 공격을 유지한다. 창병은 현재 타격 동작이 끝나 짧은 명령 동작을 한 뒤 발동한다. 지속시간과 쿨타임을 별개로 표시한다.

[구현 기본값] 쿨타임은 실제 효과가 생성된 시점부터 계산한다. 지속시간이 끝난 후부터 20초를 세지 않는다. 입력 대기 중에 LB를 바꿔도 예약된 스킬 ID는 처음 요청한 ID로 고정된다. 쿨타임 중 RB를 눌러도 자동 재사용을 예약하지 않는다. 실패 발동은 쿨타임을 소비하지 않는다.

8.2 지휘 강화

8초 동안 강감찬 검술 피해 +30%. 약공격/강공격/마무리/차징에 적용한다. 공중 공격과 공격형 대쉬에도 적용하는 것을 구현 기본값으로 한다. 창병 50 피해, 적 공격, 보호막 수치에는 적용하지 않는다.

지휘 강화 효과가 살아 있는 명중 시점의 강화량으로 피해를 계산한다 [구현 기본값]. 공격 시작 때 스냅샷한 강화와 명중 때 강화를 이중 적용하지 않는다.

8.3 창병 공격

좌우 주변 적 중 가까운 최대 5명을 찾아 각 대상당 50의 순간 피해 후 사라진다. 5명 미만이면 존재하는 적만 공격. 50을 대상 수로 나누지 않고, 각 창병 그림 수만큼 50을 중복 적용하지 않는다.

[구현 기본값] 수평 180px·수직 96px 안의 활성 생존 적을 후보로 하고 거리순, 동률이면 생성 순번순으로 선택한다. 벽으로 완전히 차단된 대상은 제외한다. 좌우 각각 5명이 아니라 총 5명이다. 보스도 후보 1명이며 근접 일반 적이 더 가까우면 그 적들이 먼저 선택된다. 보스 1명뿐이면 피해는 50이지 250이 아니다.

지휘 동작 300ms 후 그 시점의 대상을 결정한다. 대상이 없으면 효과/쿨타임 없이 “주변에 대상이 없습니다” 안내. 방패병 정면 방어는 관통하는 지원 공격으로 취급한다. 보스는 밀리지 않으며 일반 적은 작은 넉백. 출현 창병은 공격 연출용이고 장시간 AI 개체로 남지 않는다.

8.4 방패병 막기

검술을 끊지 않고 보호막 40 생성. 자연 감소/초과 피해 규칙은 §7.3. 방패병 그림은 보호막 유지 시간에만 주인공 주변을 지키고, 별도 HP/공격 AI를 추가하지 않는다. 보호막은 회복 아이템처럼 HP를 회복시키지 않는다.

9. 강화 보상과 계산

1라운드와 2라운드 보스 승리 후 다음 세 가지 중 하나를 선택한다. 같은 보상을 다시 선택할 수 있다. 선택 화면은 전투/게임 시간을 멈춘다. 선택 후 다음 라운드로 넘어가며 되돌려 다시 뽑지 않는다.

보상 ID 0회 1회 2회
sword 검술 강화 +0% +15% +30%
parry 패링 강화 200ms 250ms 300ms
command_cooldown 지휘 숙련 보상 20초 17초 14초

화면에서는 스킬 “지휘 강화”와 보상 “지휘 숙련”을 구별한다 [보상 표시명만 구현 기본값]. 효과는 확정된 공유 쿨타임 3초 감소다.

swordBonus = 0.15 × swordStacks
commandBonus = commandBuffActive ? 0.30 : 0
finalSwordDamage = roundHalfUp(baseDamage × (1 + swordBonus + commandBonus))
sharedCooldownMs = 20000 - 3000 × commandStacks
parryWindowMs = 200 + 50 × parryStacks

양수 피해의 반올림은 0.5 이상 올림. 증가율을 모두 합산한 최종 값에서 한 번만 반올림한다. 중간 단계에서 각각 반올림하거나 1.3×1.3을 곱하지 않는다. 테스트 수식에서는 정수 퍼센트(100/15/30)를 이용해 부동소수점 경계 오차를 피한다.

예: 차징3 50 + 검술1회 = 57.5 → 58. 강공격25 + 검술1회 + 지휘30% = 36.25 → 36. 차징3 50 + 검술2회 + 지휘30% = 80. 약공격 합계 37와 마무리35는 타격별로 계산/반올림하며 전체 콤보 합계를 먼저 보정하지 않는다.

사망 시 이전 라운드 보상은 유지. 새 게임/메인 메뉴 복귀 시 초기화. 성장 선택은 최대 총 2회이며 최종 보스 후에는 사용처 없는 세 번째 보상을 만들지 않는다.

소환병은 동시에 최대 3명. 초기 소환 구성은 보병2+궁병1 [구현 기본값]. 살아 있는 슬롯을 유지하고 빈 슬롯만 보충한다. 이름이 같은 재소환 개체라도 새 entityId를 부여한다. 호출 시점과 실제 생성 시점 모두 상한 검사, 예약 중인 소환도 상한에 포함한다.

소환병 HP/피해는 해당 일반 적과 동일. 소환병도 플레이어가 실제 처치하면 일반 처치 수와 주먹밥 10% 판정에 포함한다 [드롭 포함은 구현 기본값]. 최종 승리로 자동 정리된 소환병은 처치/드롭에 포함하지 않는다.

12.5 패턴 선택 알고리즘 [구현 기본값]

판정 시점에 공격을 실행 중이면 새 선택 금지. 후보는 현재 페이즈·거리·높이·쿨타임·소환 한도로 필터링한다. 우선순위는 다음과 같다.

사망 → 페이즈 전환 → 필요한 소환(소배압2페이즈) → 사용 가능한 특수 패턴 → 거리에 맞는 일반 공격 → 접근/거리 조절

같은 공격은 최대 2연속까지만 선택. 후보가 여러 개면 직전 사용시간이 오래된 패턴 우선, 동률은 고정 patternId 순. 완전 무작위 패턴 선택으로 바꾸지 않는다. 같은 공격을 반복해 플레이어를 영구 경직시키는지 검사한다.

13. 회복 아이템

주먹밥 +15HP, 일반 적 실제 처치마다 독립 10% 확률. 약초 주머니 +30HP, 전투 구역 완료마다 정확히 1개. 상자 파괴/적 기술적 제거/최종 승리 정리로 드롭을 만들지 않는다.

HP가 100이면 접촉해도 획득하지 않고 바닥에 남긴다. HP가 100 미만이면 접촉 시 즉시 회복하고 아이템을 소비한다. min(100, hp+heal). 초과 회복량을 저장하거나 보호막으로 전환하지 않는다. 인벤토리/사용 버튼은 없다.

같은 구역 안에서는 시간 경과로 없어지지 않는다. 다음 구역 진입 시 이전 구역 아이템 정리, 라운드 종료/재도전 시 모든 라운드 아이템 정리. 바닥에 닿기 전 물리적으로 떨어지는 연출을 넣더라도 획득 판정은 한 번만 한다.

[구현 기본값] 구역 클리어 약초는 출구 직전의 안전 지면에 생성한다. 클리어 이벤트 한 번에만 생성하도록 rewardSpawned 플래그를 둔다. 보스전은 별도 전투 구역 클리어 약초를 추가 지급하지 않는다. 성공 1회 플레이에서 확정 약초 수는 5개다.

이미 HP가 0인 같은 판정 틱에 뒤늦게 접촉한 아이템으로 사망을 취소하지 않는다. 보스 동시 사망 승리는 별도 우선 규칙을 적용한다.

14. 사망·승리·재도전

14.1 사망과 재도전 [확정]

현재 라운드 처음부터. HP100, 보호막0, 일시 지휘 강화 없음, 공유 쿨타임0, 이전 라운드 강화 유지. 해당 라운드의 적·보스HP·웨이브·아이템·파괴물 상태를 처음으로 되돌린다. 무제한 재도전.

입력/콤보/차징/공격 예약/피격 무적/대쉬 상태도 초기화한다 [구현 기본값]. 선택 스킬은 지휘 강화로 복귀. 라운드 재생성 시 새 attemptId와 entityId를 사용한다. 캐시된 이미지/음악을 다시 다운로드할 필요는 없다.

14.2 같은 판정 순간의 동시 사망

하나의 시뮬레이션 틱에서 피해를 모아 계산한 후 보스HP와 플레이어HP를 함께 검사한다. 둘 다 0이면 보스 처치 승리 우선. 승리 화면 뒤에 게임 오버가 늦게 나타나면 실패다.

[구현 기본값] 승리 우선 처리에서는 사망 횟수를 올리지 않는다. 결과 기록용 HP를 억지로 회복한 전투로 되돌리지 않고 승리 상태로 전환한다. 다음 라운드는 정상 HP100. 이전 틱에서 이미 게임 오버가 확정된 뒤 나중에 닿은 검격은 승리로 뒤집지 않는다.

14.3 라운드 종료

적 공격/투사체/시각 효과를 정리하고 전투 입력 차단. 바닥 회복 아이템 제거. 보호막·지휘 강화·공유 쿨타임 초기화. 1·2라운드 보상 선택 후 HP100·스킬 준비 상태로 다음 라운드. 강화 보상 스택은 유지한다.

최종 보스HP0이면 남은 소환병과 공격 효과를 제거하고 즉시 승리한다. 소환병을 더 잡아야 엔딩이 열리는 조건을 추가하지 않는다. 자동 제거는 전투 처치가 아니다.

15. 기록과 시간

결과 화면 표시 항목은 총 플레이 시간, 일반 적 처치 수, 보스 처치 수, 패링 성공 횟수, 사망 횟수. 실패한 시도의 기록도 게임 실행 세션 안에서 계속 누적한다.

검술/지휘로 처치한 일반 적과 보스 소환병을 포함하며 동일 entityId의 죽음은 한 번만 집계한다. 보스는 별도 보스 처치 수. 자동 정리·위치 보정 실패로 제거된 적은 집계하지 않는다. 새 게임/확인 후 메인 메뉴 복귀 시 기록과 강화를 모두 초기화한다.

[구현 기본값] 플레이 시간은 조작 가능한 첫 라운드 시작부터 마지막 보스 승리까지의 활성 플레이 시간을 누적한다. 재도전 중 실제 플레이, 웨이브 2초 대기, 보스 전환 연출, 짧은 히트스톱은 포함한다. 타이틀·로딩·보상선택·게임오버 메뉴·수동/자동 일시정지·엔딩·결과는 제외한다. 정확한 집계 규칙을 결과 화면 도움말에 표시한다.

총 플레이 시간은 실패 포함이므로 목표 10~15분보다 길 수 있다. 기록 저장/최고기록 표시 기능을 임의 추가하지 않는다.

16. 게임 시간과 정지

16.1 단일 시간 관리

목표 렌더60FPS, 전투는 시간 기반이다. frameCount === 12 같은 식으로 패링을 구현하지 않는다. ms 단위 타이머와 고정 1/60초 시뮬레이션을 사용한다 [고정 스텝은 구현 기본값].

시간 진행 조건 용도
simulationClock 전투 진행·히트스톱 아님 이동/공격/패링/무적/스킬/보호막/웨이브
presentationClock 게임 화면 활성·수동/시스템 pause 아님 히트스톱 해제·보스 전환 등
activePlayMs 실제 플레이 상태·수동/시스템 pause 아님 결과용 누적시간
UI time 화면 표시 중 메뉴 애니메이션·키 반복

setTimeout/Date.now()로 각각 독립된 전투 타이머를 만들지 않는다. 한 곳에서 dt를 관리한다. 스킬/보호막은 무조건 초 단위 수식으로 진행하며 React rerender 횟수와 관계없다.

16.2 일시정지 [확정]

START/Esc, 탭이 숨겨짐, 활성 패드 연결 끊김이면 자동/수동 일시정지. 움직임·공격·쿨타임·강화 지속시간·보호막 감소·웨이브 대기·페이즈 전환·기록 시간 모두 멈춘다. UI는 정지 상태에서 입력을 받을 수 있어야 한다.

정지 원인은 집합으로 관리한다: manual, hidden, pad-disconnected, focus-lost, viewport-small, runtime-error. 한 원인이 해제됐다고 다른 원인까지 지우지 않는다. 탭이 돌아와도 자동으로 전투를 재개하지 않고 계속하기 입력을 기다린다 [기본값].

패드 재연결 후 중립 상태를 한 번 읽고 새 A 입력을 받아 재개한다. 연결이 끊긴 동안 키보드로 몰래 전투가 계속되지 않는다. 처음부터 패드 없이 시작한 키보드 세션에는 이 재연결 대기를 강제하지 않는다.

16.3 히트스톱·페이즈와 교착 방지

패링 히트스톱 60ms는 simulationClock을 멈추되 presentationClock으로 해제한다. 정지된 simulationClock의 타이머로 히트스톱 해제를 예약하면 영구 정지가 되므로 금지한다. 수동 pause가 히트스톱 중 들어오면 남은 히트스톱도 멈춘다.

보스 전환은 같은 별도 연출 시계를 사용한다. 전환이 끝나면 판정·AI·효과 지속시간이 재개된다. pause 후 전환 완료 이벤트가 중복 발생하지 않아야 한다.

16.4 저FPS·탭 복귀

고정 스텝 누산기의 최대 보충은 렌더당6스텝 [기본값]. 250ms 이상의 긴 공백은 한꺼번에 피해를 밀어 넣지 않고 안전 pause로 처리한다. 정지 해제 시 이전 RAF 시각/누산기를 리셋해 수초의 누적 dt가 적용되지 않게 한다.

Phaser Arcade 물리와 도메인 업데이트의 소유자를 하나로 정한다. 수동 step과 엔진 자동 step을 동시에 실행하지 않는다. 물리를 수동 구동하면 버전3.90 API에 맞는 연결을 검증하고 step이 초 단위를 받는 점을 지킨다. [T07]

30/60/120Hz 환경에서 타이머는 같은 실시간 범위를 따르도록 시험한다. 시간 기반 판정이 저FPS 입력 샘플 손실이나 지연을 완전히 없애 주는 것은 아니다. 원시 입력 timestamp와 실제 반응 오차를 테스트 보고서에 적는다.

17. UI, 화면, 브라우저

17.1 클래식 액션 HUD [확정]

좌상단 HP바와 숫자, 우상단 라운드/웨이브, 하단 선택 지휘 스킬·공유 쿨타임. 보스전에는 보스 이름·HP바·페이즈 표시. 선택되지 않은 스킬도 공유 쿨타임 상태를 보여준다. 보호막40/감소와 지휘 강화 남은8초는 별도 작은 표시로 구별한다.

[구현 기본값] 내부 논리 배치: HP영역 (12,12,180,32), 라운드영역 오른쪽 상단, 스킬영역 y=326~354, 보스바 x=160,y=48,w=320. HUD가 보스 예고 모션을 가리지 않도록 한다. 한국어 본문은 읽기 가능한 시스템 폰트로 표시하고 이미지에 글자를 구워 넣지 않는다.

17.2 메뉴

타이틀: 게임 시작 / 조작 방법 / 설정. 설정: BGM·효과음 볼륨 각각, 전체 화면. 게임오버: 재도전 / 메인 메뉴. 일시정지: 계속하기 / 조작 방법 / 설정 / 메인 메뉴. 보상: 검술·패링·지휘 숙련 카드와 현재/선택 후 효과. 결과: 기록5종 / 메인 메뉴.

웹페이지에서 운영체제 프로그램처럼 무조건 창을 닫는 “게임 종료”를 보장하지 않는다. 메뉴 복귀로 게임 세션을 끝낸다 [구현 기본값]. 타이틀·오버레이는 패드로 이동/확정 가능하고 브라우저 권한 안내에는 클릭/키보드 접근도 가능하다.

메인 메뉴 복귀 시 “현재 진행과 강화 및 기록이 초기화됩니다. 다음 게임은 1라운드부터 시작합니다.” 확인창. 기본 포커스는 취소. 확인 전 세션을 삭제하지 않는다.

17.3 정수 확대 [확정]

내부 게임 크기는 항상640×360. 가용 CSS 픽셀 기준:

scale = floor(min(containerWidth / 640, containerHeight / 360))
displayWidth = 640 × scale
displayHeight = 360 × scale

1배 이상 중 가장 큰 정수 배율, 가로세로 중앙 정렬, 남는 공간 어두운 여백. 1920×1080 가용영역이면3배, 1280×720이면2배, 1366×768이면2배. FIT만 설정해 2.13배처럼 되는 것을 정수 확대라고 부르지 않는다. Canvas와 React HUD 부모에 같은 배율을 적용한다. nearest-neighbor/pixelated 렌더링과 pixel rounding을 사용한다. [T08]

[구현 기본값] 최소640×360보다 작은 가용영역은 분수 축소하지 않고 “창을 키워주세요” 안내 및 안전 pause. 모니터의 물리 해상도가 아니라 브라우저 실제 콘텐츠 영역을 측정한다. 브라우저 확대와 OS DPI에 따라 물리 픽셀 선명도가 달라질 수 있으므로 100% Chrome 확대에서 검수한다.

17.4 전체 화면

메인 메뉴/설정에서 게임 캔버스와 React 오버레이를 함께 포함하는 컨테이너에 전체 화면을 요청한다. 전체 화면 해제는 게임 상태를 유지하고 배율만 재계산한다. 이미 paused였다면 paused를 유지한다. 이 동작만으로 HP/스킬/라운드가 초기화되면 실패다.

Esc가 전체 화면을 해제한 경우 같은 입력으로 게임 pause를 중복 실행하지 않는다. fullscreenchange와 Esc 처리기를 묶어 이벤트 순서에 대응한다. 기본 동기화 허용구간120ms. 이후 새 Esc 입력은 정상 pause다.

브라우저 전체 화면과 오디오 권한은 단순 게임패드 폴링이 사용자 활성화로 인정된다고 가정하지 않는다. 실패 시 클릭/Enter 같은 신뢰 가능한 입력 안내를 제공한다. 게임패드 전투 우선 정책과 별개로 권한 UI 입력은 허용한다. 사용자의 브라우저 보안 설정을 끄게 하지 않는다. [T09][T10]

21. 로딩·실행·오류

21.1 전체 일괄 로딩 [확정]

게임 시작 전에 등록된 모든 런타임 리소스를 한 번에 준비한다. 공통/라운드별 지연 로딩으로 바꾸지 않는다. atlas 하나로 모든 포함 프레임을 로딩하므로 편집용 개별PNG까지 중복 로딩하지 않는다.

단계: manifest 유효성 검사 → 이미지/atlas/음원 로딩 → 필수 frame 존재 검사 → 생성형 임시 texture 준비 → 시작 가능. 진행률과 실패 파일명을 보여준다. 없는 경로를 코드가 알아서 추정하지 않는다.

로딩 실패 시 “리소스를 불러오지 못했습니다” + 오류 파일 + 다시 시도. 완료된 리소스는 중복 등록하지 않고 실패 항목만 다시 시도한다. 로딩 중 다시 시도 버튼 연타는 하나의 요청만 생성한다. 파일당 제한15초는 구현 기본값.

21.2 웹 실행

개발은 npm run dev, 배포 빌드 npm run build, 확인 npm run preview. 산출물은 dist/. 런타임 비밀키/로그인/서버가 필요 없는 정적 사이트를 기준으로 한다. 외부 CDN 폰트/이미지/음악을 런타임 필수로 사용하지 않는다. 에셋 경로는 import.meta.env.BASE_URL 등 동일한 기준으로 만들고 하위 경로 배포에서도 검증한다.

일반 file:// 직접 열기는 실행 조건이 아니다. 배포 시 HTTPS, 개발 시 localhost를 사용한다. 게임패드와 웹 권한 지원이 달라질 수 있는 iframe 배포는 기본 검수 범위에 넣지 않는다.

21.3 예외 시 데이터

치명적 오류가 나면 전투를 멈추고 오류 안내/현재 라운드 재시도/메인 메뉴를 제공한다. 메모리 세션이 살아 있을 때만 강화/누적 기록을 보존할 수 있고 새로고침 복구를 약속하지 않는다. 손상된 세션을 조용히 정상 진행시키지 않는다.

22. 지형 끼임과 진행 안전장치

움직이라는 AI 의도가 있는데 2초간4px 미만 이동하고 장애물이 막은 경우를 끼임 후보로 한다 [기본값]. 공격 준비·회복·패링 경직·의도적 궁병 대기는 후보가 아니다. 안전 위치 검색→짧은 생성 예고→위치 보정. HP와 동일 entityId를 유지한다.

안전 지점은 같은 잠긴 구역, 유효 지면, 장애물 겹침 없음, 플레이어와 최소120px, 가능한 한 화면 끝의 예고 가능한 곳. 새 적으로 다시 카운트하거나 드롭을 주지 않는다.

안전 지점이 없으면 500ms 간격3회 재탐색 [기본값]. 실패 시 technicalRemoved로 예외 정리하고 웨이브 진행을 막지 않되 처치/드롭은 없음. 이 비정상 완료를 오류 로그·기록 무결성 경고에 남긴다. 최종 정상 완주 테스트에서는 기술적 제거가 한 번도 일어나지 않아야 한다.

맵 밖으로 나간 적도 같은 절차. 플레이어는 마지막 안전 지면으로 복귀하고 개발 경고를 남긴다 [기본값]. 의도적 죽음 구간이 아닌데 낙하로 게임을 계속할 수 없게 만들지 않는다.

23. 성능·테스트·완료 기준

23.1 목표와 측정 [확정 + 측정 기본값]

60FPS 목표, 고정 웨이브 최대6명, 최종 보스+소환병3명, 창병최대5대상, 보호막/차징/검격 효과, 전체 화면, 패드 재연결을 포함해 테스트한다. 모든 PC에서60FPS를 보장한다고 쓰지 않는다.

측정 기본값: 참조PC/OS/GPU/Chrome버전/모니터Hz 기록, 10초 워밍업 뒤60초 측정, 평균58FPS 이상·프레임시간 p95≤20ms를 목표로 한다. 연속3프레임을 넘는50ms 이상 끊김이 반복되면 원인을 수정한다. 다른 모니터 주사율에서는 렌더 수치와 시뮬레이션 시간의 차이를 기록한다.

효과/투사체/적 풀링, 카메라 밖 불필요한 시각 갱신 감소, UI10Hz, 불필요한React state 반복 제거를 적용한다. 성능 때문에 패링 시간/동시 적 수/보스 패턴을 몰래 삭제하지 않는다.

23.2 기능 완료 게이트

npm run typecheck, npm run test, npm run build 성공. E2E에서 시작→1보스→보상→2보스→보상→3보스→엔딩→결과, 사망→재도전, 탭숨김 pause, 리소스 실패 재시도 동작. 실제 Xbox형 패드로 연결·해제·재개를 수동 확인한다.

테스트 코드에서만 보스 즉시처치/라운드 점프를 사용할 수 있고, 일반 배포 빌드에는 치트가 노출되지 않아야 한다. 가상패드 테스트만으로 실제 기기 호환 검증을 완료했다고 하지 않는다.

3라운드 전체 기능, 실제 게임용 그래픽/음원 교체, 정상 완주, 명세 수치 회귀 테스트, 자산 출처/사용권 기록, 알려진 문제 목록, 실행 방법과 검증 결과까지 있어야 최종 완료다.
