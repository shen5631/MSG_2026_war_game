# 구현 순서와 개발 완료 기준

## 1. 시작 원칙

기획서를 또 작성하는 단계가 아니라 실행 가능한 게임을 구현한다. 단계별로 진행하지만 최종 범위는 3라운드 전체다.
아래는 작업 순서이지 소요 시간 보장표가 아니다. 확정 규칙을 삭제하여 일정에 맞추지 않는다.

## 2. 환경 초기화

먼저 `node --version`, `npm --version`, 현재 파일과 package.json 유무를 확인한다.
Node 기준은22.12+인22.x. 이미 적합한 환경이면 재설치를 강제하지 않는다.
기존 React 프로젝트가 있으면 라우팅/스타일/설정 충돌을 확인하고 병합한다.
빈 폴더라면 문서와 자산을 보존한 채 React-TS Vite를 구성한다. 생성기가 폴더를 비우게 두지 않는다.

### 초기 명령 예시

```bash
# 현재 폴더가 이미 이 패키지로 채워져 있으므로 별도 임시 폴더에서 scaffold 후 필요한 파일만 병합한다.
npm create vite@latest __vite_scaffold -- --template react-ts
# package.json, tsconfig, vite config, index.html, src 파일을 검토하여 루트에 병합한다.
# public/assets, docs, spec, CLAUDE.md를 덮어쓰지 않는다.
npm install
npm install --save-exact phaser@3.90.0
npm install --save-dev --save-exact vitest @playwright/test
# 필요 시 Playwright가 요구하는 브라우저 설치를 사용자 환경에서 수행한다.
npx playwright install chromium
```

React/TS/Vite의 호환 안정 버전을 확인해 정확한 버전으로 고정하고 lockfile을 만든다. 위 설치가 현재 환경에서 실행되었다고 미리 보고하지 않는다. package audit 결과를 읽고 보안 문제를 기록한다. 구버전/신버전 Phaser 문서를 혼합하지 않는다.

### scripts 계약

| script | 동작 |
|---|---|
| dev | Vite 개발 서버 |
| typecheck | TypeScript 타입 검사, 결과 산출물 불필요 |
| test | Vitest 단위시험 1회 실행 |
| test:e2e | Playwright 브라우저 시험 |
| build | 타입 검사 후 Vite production build |
| preview | production build 확인 서버 |
| verify:assets | 자산 경로·atlas frame·크기·결손 상태 검사 |

Python은 이 전달 패키지 검사에만 사용하며 게임 실행 필수 의존성으로 만들지 않는다.

## 3. 단계별 작업

### P0 — 실제 자산이 표시되는 실행 뼈대

산출물: package/tsconfig/Vite 설정, React GameHost, Phaser Boot/PlayScene, 로더, 중앙 이벤트 브리지.

640×360 화면에 v2 idle 프레임을 표시하고 창 크기별 정수 확대/여백을 구현한다. React StrictMode 재마운트 때 중복 캔버스/리스너가 생기지 않아야 한다. 메뉴는 키보드/패드 공통 액션을 사용한다.

통과 조건: `npm run dev`, `typecheck`, `build`; sprite alpha와 발 기준점이 보임; 누락된 texture 경로가 없음.

### P1 — 순수 도메인과 입력·시계

산출물: 타입/SessionStore/GameClock/PauseReasons/InputRouter/장치 어댑터/단위시험.

입력 신호를 프레임 번호 대신 pressed/held/released와 시간으로 추상화한다. 데드존/트리거 임계/패드 우선/탭 정지/메뉴 입력 소비를 구현한다. B+Y100ms와 실행 취소/버퍼를 단위시험으로 만든다. 피해/강화/보호막 수식은 Phaser 없이 테스트한다.

통과 조건: 기본 피해수식·보호막·쿨타임·pause 테스트 성공. 패드가 없어도 키보드 조작 가능. 화면 전환 A가 점프가 되지 않음.

### P2 — 주인공 전투 수직 구현

산출물: 이동·걷기/달리기·점프·대쉬·약3타·강/마무리·차징3단계·패링·피격·사망.

테스트용 보병1명과 표적을 만든다. 시각 자료가 부족한 heavy/charge/command는 명시적 fallback binding으로 연결하고 `temporaryAssets`에 남긴다. 공격 판정은 시각 프레임과 독립한다.

통과 조건: 보병40HP, 약3타37, 마무리후처치. RT 무적 없음. 패링 성공 자동피해 없음. charge 취소/방출 정확. 원본 그림 잘림을 frameWidth 변경으로 감추지 않음.

### P3 — 지휘·회복·일반 적·첫 라운드

산출물: 스킬3종, 적5종 기본 클래스, 회복/드롭, 구역잠금·웨이브·엄폐/파괴물, 선봉대장2페이즈.

1라운드9명/3웨이브/보스350HP를 명세 그대로 구현한다. 지휘공유20초와 최대5대상, 보호막40/초8, 약초1개/구역을 시험한다. 적 AI는 공통 상태기계와 종별 데이터로 나누고 단순 색상만 바꾼 동일 AI로 끝내지 않는다.

통과 조건: 일반 웨이브 끝까지 정상 진행, 보스승리/동시사망/게임오버/재도전 정상, 임시 리소스 여부 명시.

### P4 — 전체 3라운드와 성장

산출물: 2·3라운드 맵, 창병장·소배압, 5구역/13웨이브, 보상선택, 소환병3명제한.

기획 JSON을 데이터로 읽어 적 조합을 반복 입력하지 않는다. 같은 강화2회 및 혼합 선택을 모두 테스트한다. 모든 보스 공격의 준비·활성·회복 및 패링불가 붉은표시를 연결한다.

통과 조건: 새게임부터3보스까지 진행 가능, 보상2회만, HP/버프/쿨타임의 라운드 및 retry 리셋 구분, 50명고정배치 불변.

### P5 — UI·엔딩·사운드·기록

산출물: 타이틀/설정/일시정지/보상/오류/엔딩/결과, 기록5종, 사운드 채널.

A로장면진행, 입력 중복 방지, 모든 도전 기록 누적, 실제처치와기술적정리구분. 전체화면권한/오디오활성화 실패는 명시적UI를 제공한다. BGM+SFX 개별 볼륨, pause 오디오 정상 복구.

통과 조건: 결과는 실제통계, 최종보스이후잔여공격피해없음, 창작과역사구분, 로딩실패재시도.

### P6 — 브라우저·성능·복구

산출물: 상세테스트, 메모리/프레임시간 측정, 게임패드실기 체크리스트, 적끼임안전장치.

최대6명웨이브, 소배압+3소환병, 창병지원+여러효과, 화면전환/숨김/해제/재연결 반복. 재도전20회·메뉴전환20회에서 중복 리스너/버퍼/음악 확인. 진행막힘은 정상테스트에서0회여야 함.

통과 조건: 타입/단위/E2E/빌드 성공 및 실제한판완주. 실기패드없는경우 미검증 명시.

### P7 — 최종 리소스 교체와 납품 점검

누락된 최종 픽셀아트/배경/아이콘/음원을 교체한다. 포즈재활용과 생성형임시자료를 사용자에게 숨기지 않는다. 한판완주와 전투회귀시험을 다시 한다. 실제 플레이 시간이600~900초인지 측정한다.

통과 조건: 기능완료와리소스완료 두가지 모두 충족. 불가능한 항목은 전체완료라고 하지 않고 남은항목을 정확히 보고한다.

## 4. 개발 중 디버그 기능 [개발 빌드 전용]

히트박스/몸통바디/발앵커/공격상태/클록/pause원인/스킬쿨타임/적entityId/웨이브생존수를 표시한다.
특정라운드입장·HP설정·스킬준비·보스HP50%·로딩실패·가상패드해제 테스트훅을 제공할 수 있다.
production에서 훅과무적키를 노출하지 않는다. 정상플레이데이터가 아닌 테스트완주 기록은 결과에서구분한다.

## 5. 하지 말 것

- 원형/사각형 적 몇 개만 놓은 화면을 게임 전체완성으로 보고.
- 그래픽이 없다고 차징/지휘/보스2페이즈를 생략.
- runtime 에러를 try/catch로 덮고 성공토스트만 띄우기.
- HTML에 원본 스프라이트 안내판을 통째로 붙이고 캐릭터로 사용.
- 최초나중의 모든예외를 무시하고 Phaser scene.restart만으로 세션리셋을 처리.
- 게임프레임수와 전투시간을 동일시.
- 테스트를 실행하지 않고 통과했다고 기록.
